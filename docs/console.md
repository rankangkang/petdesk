# 控制台与底座配置

PetDesk 的角色是承载用户提供的宠物。应用图标使用胡桃形象，但应用不依赖特定宠物；首次打开时可导入用户自己的宠物。发行包可选择附带内置宠物。

## 从导入到使用

首次打开显示宠物库的空态，直接提供导入入口。正常库页面保留导入按钮与格式帮助，也支持拖入文件夹。选择目录后，先验证最终图片，再显示名称、形象和能力预览；用户可选择仅导入、导入并使用或取消。

macOS 文件选择器从用户主目录开始，避免 Qt 在显示系统选择器前访问受保护或暂时不可用的旧目录；具体宠物目录由用户在选择器中指定。其他系统保留最近导入位置。

控制台采用白色内容区、浅灰导航和简洁的分组设置。库详情使用素材的首帧显示预览；选择时临时读取图集，只缓存裁剪后的预览。应用内容使用 Qt Fusion 和统一样式保持接近，系统标题栏与文件选择器继续使用原生界面。自绘开关仍是可访问的 Qt 复选框，可通过键盘操作。

仅导入不会更换正在运行的宠物。浏览列表也不会自动激活，点击「使用桌宠」才切换。使用后保留控制台并进入当前桌宠的设置页。

## 库与可恢复移出

活动宠物位于数据目录的 `pets/<content-key>`。移出时原子改名到 `pets/.removed/<content-key>`，不删除原始目录，也不永久删除本地副本。「已移出」页可恢复。活动和已移出记录都拒绝无效标识或目录符号链接。

同一图像字节与名称确定同一个键，保持已有去重规则。再次导入已移出的记录会恢复，不累积第二份副本。恢复前重新校验图片，损坏记录会保留在已移出目录并报告原因。

可选发行包通过可执行文件旁的 `bundled-pets/manifest.json` 指定内置宠物及其内容键。启动时复用已有记录、恢复已移出记录或导入缺失素材；内置标记由当前发行包决定，不能在库中移出。用户自行导入的其他宠物仍可移出。

清单格式为 `{"version": 1, "pets": [{"id": "example", "directory": "example", "key": "..."}]}`；目录相对于 `bundled-pets`，内容仍为标准宠物包。`key` 是图集文件的 SHA-256 十六进制摘要、一个 NUL 字节和宠物显示名的 UTF-8 字节拼接后的 SHA-256 十六进制摘要。可用 `PetDesk --validate <目录>` 获取图集摘要和解析后的显示名。目录名、id 使用小写英文字母、数字、连字符或下划线。

## 设置归属

`Preferences` 使用数据目录内的 INI 配置。`pets/<key>/...` 保存每只桌宠的大小、注视、自动活动、散步和活动频率。启动行为、关闭行为、暂停、可见性和最近位置属于宿主。v1 的注视选项不可操作；所有动作预览在暂停时禁用。

大小滑杆支持 50%–200%，可以使用键盘方向键微调，并在旁边显示当前数值。

迁移只在新设置文件不存在时读取旧版 QSettings。把上次已选宠物的旧全局设置归入对应键，保留已有宠物库、位置和暂停设置；新宠物使用默认值。显式指定 `--data-dir` 的测试配置不读取个人旧设置。

## 入口与生命周期

默认启动即打开控制台。macOS 以菜单栏应用运行，不占用 Dock；点击菜单栏图标打开原生菜单。Windows 通知区域的左键打开控制台，右键打开菜单；通知区域图标可能被系统放进折叠区域。关闭窗口默认收起，另有明确的退出按钮；应用偏好可选择关闭即退出。收起控制台后，桌宠右键、系统入口和再次打开应用均可找回窗口。

macOS 接收公开的 reopen AppleEvent 来处理再次打开应用。其他重复进程通过数据目录内的原子请求文件唤起已有控制台，由 QFileSystemWatcher 监听，不使用轮询、TCP、后台进程或 Agent。

导航和宠物项使用可访问的原生按钮，避免依赖旧 Qt 的合成表格辅助功能接口；切换当前宠物时复用已有条目。关闭控制台不会拒绝应用的显式退出。

控制台展示时自动活动暂歇，用户仍可手动试播；隐藏或暂停桌宠会停止相关计时器并清空旧活动。找回位置按钮将桌宠移到所选屏幕工作区内，避免多显示器切换后无从找回。

## Mac 运行库要求

[Qt 官方修复 ae0bd2c](https://github.com/qt/qtbase/commit/ae0bd2c52d5e7f112dcace027b4d279b532e1b86)修复 Cocoa 辅助功能缓存的引用计数问题；Qt 6.9.0 不含该修复。本次使用官方 Qt 6.9.3 SDK，项目 SDK 与个人 Homebrew Qt 分开存放。

macOS 27 的菜单栏事件可能不是鼠标事件；Qt 6.9.3 的托盘实现仍直接读取 `clickCount`，会在菜单打开时触发 AppKit 异常。Qt 后续代码在访问前增加了事件类型检查。PetDesk 的 macOS 入口使用 AppKit 的 `NSStatusItem` 和 `NSMenu`，不创建 Qt 托盘对象，避免经过该路径；Windows 和 Linux 继续使用 Qt 系统托盘。参见 [Qt 6.9.3 的实现](https://github.com/qt/qtbase/blob/v6.9.3/src/plugins/platforms/cocoa/qcocoasystemtrayicon.mm)与[后续实现](https://github.com/qt/qtbase/blob/6.12/src/plugins/platforms/cocoa/qcocoasystemtrayicon.mm)。

打包通过 `qt.conf` 和运行时插件路径限制，仅从应用内的 `Contents/PlugIns` 加载插件，避免误装载其他 Qt 环境。使用包内 SDK 构建，检查所有 Mach-O 的外部依赖，最后执行 ad-hoc 签名与验证。依据是 [Qt 的 qt.conf 路径规则](https://doc.qt.io/qt-6/qt-conf.html)。
